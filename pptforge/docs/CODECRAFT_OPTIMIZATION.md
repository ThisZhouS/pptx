## 二、做了什么

### 1. 字体可用性（698 + 124 处）

`MiSans Normal` / `汉仪刚艺体-85W` → `Microsoft YaHei`，包括 `theme1.xml` 的 `fontScheme`
与每页 run 的 `latin` / `ea` / `cs`。

这台机器上缺字体时 PowerPoint 本来就回退到雅黑，所以**本次替换在渲染上零差异**
（导出 PNG 的 ink ratio 与原件逐页一致），但保证换到没装这两款字体的演示机上不会变成宋体。

### 2. 全篇切换

| 页型 | 切换 |
| --- | --- |
| 封面 / 章节页（1,3,6,12,16,19） | `fade-smoothly` 0.8s |
| 其余内容页 | `fade` 0.6s |

统一克制：不抢内容，翻页有呼吸感。

### 3. 分组动画（101 个效果）

按每页形状的语义自动编排，不逐页写死：

| 页型 | 编排 |
| --- | --- |
| 封面（3 形状） | 标题淡入 → 日期 / 汇报人随后 |
| 目录（14 形状） | 标题淡入 → 「01 + 核心理念与痛点」成组出现 → 依次 02/03/04（编号 zoom、名称 fade） |
| 章节页（2 形状） | 编号 zoom → 标题淡入 |
| 内容页（4–15 形状） | 标题淡入 → 装饰条随标题擦出 → 配图 zoom → 正文淡入 → 剩余装饰补出 |

每页动画数：1 页 3 个、2 页 10 个、3/6/12/16/19 页各 2 个、4 页 15 个、5 页 10 个、
7–11/14/15/17/18 页各 4–5 个、13 页 9 个。

### 4. 溢出修复（2 处）

第 4 页两张卡片的正文（"深度分析代码仓库" / "提供重构方案"）文字宽度 240pt 超过框宽 224pt，
给这两个文本框写了 `<a:normAutofit fontScale="92000"/>`（自动缩到 92%），其余文本不动。

**没动的**：目录页 `01/02/03/04` 大号编号的"溢出"是设计意图（PowerPoint 正常溢出显示），
以及 7 处窄装饰条——它们的"文本"是空行高，属于检测误报。

## 四、一个值得记住的坑

一开始用 PowerPoint COM 给文本框设 `TextFrame2.AutoSize` 再 `pres.Save()`，结果：

- `AutoSize` 在只读复检时**看起来没生效**（`BoundWidth` 仍是旧值）；
- 更严重的是，PowerPoint 保存会重新序列化 XML，**手写的 101 个动画掉了 3 个**（变成 98）。

所以最终改成：COM 只读扫描出"哪些框超宽 + 该缩到多少"，然后把 `normAutofit fontScale`
写进 XML（python-pptx 保存），动画数保持 101。

结论：**改动效/时间轴的文件，不要用 PowerPoint 的 Save 收尾**。

## 五、没做的（保持原设计意图）

- 不改任何文字、不移动任何形状、不改配色与图片；

- 不给正文做"按段落分条"——这些页面是卡片式短文，整块出现比逐字出现更稳。

## 六、追加：章节页改造为 morph 转场序列

产物：`samples/codecraft-morph-chapters.pptx`（27 页）

按四步流程（见 `docs/MORPH_WORKFLOW.md`）把 4 个章节页各扩成 3 帧：

| 步骤 | 动作 |
| --- | --- |
| ① 拆解 | `decompose_deck` 找出 4 个章节页（第 3/6/12/16 页，含 `01`–`04` 编号），再用 COM 读出编号与标题的实际几何（编号 100pt、标题 48pt） |
| ② 编码 | 章节页的编号/标题改名 `!!num` / `!!title`；新帧用同一 layout 的占位符、同名 → morph 可插值 |
| ③ plan | 每章 3 帧：起点（编号居中放大 `(3.9,1.5) 5.6×4.2`，标题在下方 `y=5.9`）→ 中间点（编号缩到左上 `(0.9,0.55) 1.6×1.3`，标题上移 `y=0.7`）→ 终点（原章节页） |
| ④ 编写 | 同 layout 新建两帧插到章节页之前；三页都设 `morph` 1.2s + `advTm`（帧 1.4s / 章节页 2.0s）；章节页清空页内对象动画 |

最终页序（27 页）：

```
1 封面 · 2 目录 · 3-5 章节01 三帧 · 6-7 内容 · 8-10 章节02 三帧
· 11-15 内容 · 16-18 章节03 三帧 · 19-21 内容 · 22-24 章节04 三帧 · 25-27 内容/结尾
```

验证：

| 检查 | 结果 |
| --- | --- |
| 12 页 morph（4 章 × 3 帧） | COM 回读 `EntryEffect=3954`，其余页仍是 `fade` / `fade-smoothly` |
| 元素编码 | `!!num` / `!!title` 出现在 3/4/5、8/9/10、16/17/18、22/23/24 各三页 |
| 内容页对象动画 | 101 个动画原样保留（只清空了章节页的） |
| `validate` | 27 页 / 27 页有切换 / 0 problem |
| 渲染 | 27 页 PNG 正常；章节帧背景与章节页一致（同 layout 继承） |

踩到的坑：帧的最终页码不能用"插入那一刻的索引"记录 —— 从后往前插时，后续插入会让已处理章节的页码继续右移。
正确算法是 `最终页码 = 原页码 + 2×(排在前面的章节数) + 2`（自己在前面插的两帧）。
第一版用中间态页码，结果把 morph 打到了内容页上（虽然内容页动画没丢，但有两页章节帧没被设上）。

## 七、重调：拿真实设计师模板做参照

上一版效果差的根因不是代码，是**参数靠感觉**。这次下了两个人类设计师做的带动画模板做基准
（`samples/templates/`，来自 [Creative Venus](https://creativevenus.com/)，免费可商用、免注册直链）：

| 模板 | 页数 | 切换 | 对象动画 |
| --- | --- | --- | --- |
| `blue-glow-ai-platform` | 5 | `p:fade` | 146 个 |
| `movement-elements` | 10 | `p159:morph` × 10，**`p14:dur=2000`** | **0 个** |

### 模板给出的三条硬参数

1. **进入效果几乎所有都用 `presetID 42`「上升」(Ascend)** —— 146 个动画里 124 个是它。
   不是原地淡入，是"从下方轻微上浮 + 淡入"。
2. **时长 800ms 是主流**（372 个 800ms，600–700ms 只有 19 个）。我原来用 400–600ms，偏快。
3. **触发用 `withEffect` 占 141/146** —— 靠 **delay 错峰**做瀑布，而不是 `after_previous` 一个等一个。
   我原来是 61 个 afterEffect 串行，节奏发"顿"。

模板的作者原话（页面正文）：每页动效预算 ≈3 秒、单次 0.5 秒够、只给值得的页加、
"十页连续运动会让观众等着而不是看着"。

### 改了什么

| 项 | 旧 | 新 |
| --- | --- | --- |
| 进入效果 | `fade` 64 / `zoom` 24 / `wipe` 13 | **`ascend` 90（100%）** |
| 时长 | 500ms×112 / 600ms×60 / 400ms×54 | **800ms × 90** |
| 触发 | `afterEffect` 61（串行） | **`withEffect` 78 + stagger 0.12s** |
| 章节切换 | `morph` 1.2s | **`morph` 2.0s**（对齐模板的 2000ms） |
| 章节帧位移 | 从屏幕中央飞向左上（跨度大） | 原地**上浮 1.4 英寸**，尺寸不变 |

引擎侧改动：`motion.py` 四个套餐重写（`ascend` + 0.8s + `stagger`），
`deck._anim_items` 支持 `stagger` 累积 delay，`morph.py` 默认 `duration 2.0` / `frame_duration 2.5`。

### 顺带修掉的两个真 bug

1. `patch_deck` 里 `if patch.get("animations")` —— 空列表是 falsy，**传 `[]` 根本清不掉动画**。
   改成 `if "animations" in patch`。
2. 即使进了分支，也写成 `set_slide_timing(...) if items else {"items": 0}` —— 空列表时**直接短路返回**，
   旧的 `p:timing` 没被移除。改成无条件调用（函数内部本来就会先移除旧 timing）。

如果没有第 2 条，章节页会同时带着 morph 和页内动画 —— 时间轴打架，正是"看着别扭"的来源之一。
